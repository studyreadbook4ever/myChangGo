상단 1920×720 영역을 N명이 정확히 균등 분할한다.

각 출연자 i의 영역은 다음 공식으로 계산한다.

left_i  = round(1920 × i / N)
right_i = round(1920 × (i + 1) / N)
width_i = right_i - left_i

i는 0부터 시작한다.

2명: 각 960×720
3명: 각 640×720
4명: 각 480×720
5명: 각 384×720
6명: 각 320×720

모든 칸을 합쳤을 때 정확히 1920픽셀이 되어야 한다.

   - 아바타가 너무 작게 보이지 않도록 확대
   - 다른 출연자들과 머리 크기가 지나치게 차이 나지 않도록 시각적 크기를 정규화

9. 아바타가 실제로 안전 영역 밖으로 크게 움직이는 경우에만 0.5초 이상의 부드러운 키프레임 이동을 사용한다.

[프레임 단위 싱크 절차]
──────────────────────────────

이 작업에서 가장 중요한 것은 4개의 파일 길이를 같게 만드는 것이 아니라, 실제 음악과 영상의 동일 순간이 같은 출력 프레임에 오도록 만드는 것이다.

1. 먼저 ffprobe와 실제 디코딩을 사용해 각 소스의 다음 정보를 기록한다.
   - 영상 첫 decoded PTS
   - 오디오 첫 decoded PTS
   - 원본 fps와 time base
   - 해상도
   - 오디오 sample rate
   - 지정 구간의 실제 프레임 수
   - VFR/CFR 여부

2. ffprobe CSV의 행 번호와 zero-based 프레임 번호를 혼동하지 않는다. 내부 프레임 번호는 전부 zero-based로 통일한다.

3. 각 원본의 오디오를 비압축 PCM으로 추출하여 싱크를 분석한다.

4. 보컬 첫 음절만으로 영상을 정렬하지 않는다. 사람마다 노래를 부르는 타이밍과 마이크 지연이 다를 수 있다.

5. 공통 반주, 드럼, 베이스, 박자 성분을 우선 사용한다. 필요하면 35~250Hz 부근의 저역 반주를 분리해 NCC, GCC-PHAT 또는 동등한 상관 분석을 수행한다.

6. 곡 시작점 한 곳만 검사하지 않는다. 초반·중반·후반 및 주요 구간을 포함하여 전 구간 최소 10~16개 분석 창에서 상대 지연을 측정한다.

7. Live2D 아바타의 입 움직임은 캡처·트래킹 지연이 있을 수 있으므로 입 모양만 보고 전체 영상 오프셋을 결정하지 않는다.

8. 각 구간의 지연값을 비교하여 다음을 구분한다.
   - 고정 시작 오프셋
   - 지속적인 시계 드리프트
   - 원본의 특정 지점에서 발생한 프레임 누락
   - 프레임 중복
   - 캡처 불연속
   - 보컬 자체의 박자 차이

9. 기준 출연자가 지정되어 있으면 그 영상 타임라인을 기준으로 삼는다. AUTO이면 가장 연속적이고 불연속이 적은 소스를 타임라인 기준으로 선택한다.

10. 모든 비기준 영상을 가장 가까운 1/60초 정수 출력 프레임에 매핑한다.

11. 프레임보다 작은 잔차는 전 구간 오차가 가장 작아지는 인접 프레임을 선택한다.
    60fps에서 이론상 가장 가까운 프레임의 최대 양자화 오차는 약 8.33ms다.

12. 속도를 비율로 늘이거나 줄이지 않는다.
    다음 방식은 기본적으로 금지한다.
    - 임의 setpts 배속
    - atempo
    - 전체 구간 타임스트레치
    - 오디오 피치 변경
    - 싱크를 위한 무분별한 리샘플링

13. 미세한 불연속은 꼭 필요한 위치에서만 정수 프레임을 삭제하거나 복제하여 보정한다.

14. 프레임 삭제는 그 지점 이후의 원본 프레임 인덱스를 +1 진행시키고, 프레임 홀드·복제는 이후 인덱스를 -1 지연시키는 효과임을 계산표로 검산한다.

15. “한 프레임을 총 5번 표시”와 “원래 프레임에 복제본 4개 추가”를 혼동하지 않는다.

16. 프레임 삭제·복제 위치는 가능하면 움직임이 적고 장면 변화가 없는 곳을 선택한다.

17. 노래 중간의 음악이나 최종 마스터 오디오는 프레임 보정 때문에 잘라 붙이지 않는다. 영상 패널만 보정하고 마스터 오디오는 연속성을 유지한다.

18. 시작 오프셋이나 드리프트 분석 결과가 갑자기 수백 ms 이상 변하면 바로 적용하지 말고 다음을 재검사한다.
    - 입력 타임코드 해석
    - 오디오 첫 PTS
    - 영상 첫 PTS
    - URL 구간 추출 정확도
    - 프레임 번호 off-by-one
    - 잘못 선택한 상관 피크

19. 싱크를 맞춘다는 이유로 전체 영상에서 3초, 5초처럼 큰 구간을 무작정 제거하지 않는다.

20. 각 출연자에 대해 다음을 표로 기록한다.
    - 시작 source frame
    - 시작 output frame
    - 시작 PTS
    - 초기 오프셋
    - 프레임 삭제 위치
    - 프레임 복제 위치
    - 보정 전 잔차
    - 보정 후 잔차

21. 목표 싱크 품질:
    - 전체 분석 창의 잔차가 모두 1프레임 미만
    - 평균 또는 중앙 잔차는 가능하면 0.25프레임 이하
    - 어느 한 구간만 맞고 뒤에서 밀리는 결과는 실패로 간주

──────────────────────────────

1. 최종 출력 프레임 수를 렌더 전에 확정한다.

2. 최종 프레임 수:
   OUTPUT_FRAMES = 최종 길이(초) × 60

3. 예:
   254초 × 60 = 15,240프레임

4. 프레임 수를 맞추기 위해 노래 일부를 제거하지 않는다.

5. 원본 구간이 노래보다 1~3초 길게 설계된 경우 그 여백을 그대로 보존한다.

6. 짧은 소스가 끝 여백에서만 몇 프레임 부족하면 마지막 정상 프레임을 홀드할 수 있다.

7. 노래가 진행 중인 구간이 통째로 부족하면 정지화면으로 숨기지 말고 소스 부족으로 보고한다.

8. 모든 패널은 최종 프레임까지 존재해야 하며, 검은 프레임으로 끝나서는 안 된다.

[단일 오디오 마스터 선택]
──────────────────────────────

1. 최종 오디오는 출연자 중 정확히 한 명의 원본 오디오만 사용한다.

2. 서로 다른 출연자의 오디오를 섞거나 동시에 재생하지 않는다.

3. 오디오 마스터가 지정되어 있으면 그 소스를 우선한다. 단, 파일 손상·심각한 클리핑·누락이 발견되면 보고한 뒤 다른 후보를 선정한다.

4. AUTO-QUALITY이면 다음을 종합 비교한다.
   - 원본 오디오 코덱과 비트레이트
   - sample rate
   - 노이즈
   - 클리핑
   - 순간적인 끊김
   - 주파수 대역 손실
   - LUFS
   - LRA
   - True Peak
   - 전체 구간의 연속성

5. 단순히 비트레이트 숫자가 가장 높다는 이유만으로 선정하지 않는다.

6. 선택한 오디오는 영상 기준 타임라인에 맞게 시작점만 정확히 정렬하고 이후에는 연속된 하나의 트랙으로 유지한다.

7. 오디오 게인이 숫자로 지정되면 정확히 그만큼만 적용한다.

8. AUTO-PEAK-SAFE이면 불필요한 압축·EQ·노이즈 제거 없이 True Peak가 -1dBTP를 넘지 않도록 단일 게인만 적용한다.

9. 사용자의 지시 없이 리미터, 컴프레서, 리버브, 스테레오 확장, 음색 보정을 적용하지 않는다.

10. 렌더 명령에서 다른 모든 입력 오디오를 명시적으로 제외하고 선택한 마스터 오디오 하나만 map한다.

[자막 타이밍]
──────────────────────────────

1. 가사에 타임코드가 있으면 그 값을 초기값으로 사용하고 실제 오디오를 기준으로 확인한다.

2. 가사에 타임코드가 없으면 선택한 마스터 오디오의 실제 발음 시작점과 음악 구절을 분석하여 각 cue의 시작·종료 프레임을 결정한다.

3. 자동 음성 인식 결과만 믿지 말고 파형·스펙트로그램·실제 렌더 프레임으로 확인한다.

4. 자막 시작과 종료는 60fps 정수 프레임에 스냅한다.

5. ASS의 시간 단위는 1/100초이므로 프레임→ASS 시간 변환 시 다음 규칙을 사용한다.

   ass_centisecond = floor(frame_number × 100 / 60)

6. 단순 반올림이나 올림을 사용해 자막이 목표 프레임보다 한 프레임 늦게 등장하지 않도록 한다.

7. 연속된 두 가사는 앞 자막의 종료 경계와 다음 자막의 시작 경계를 동일하게 사용한다.

8. 의도적인 무가사 구간이 아닌데 자막 사이에 한 프레임 공백을 만들지 않는다.

9. 두 자막이 한 프레임 동안 겹쳐 표시되지 않도록 한다.

10. 모든 cue에 대해 다음을 자동 검사한다.
    - 목표 시작 전 프레임에는 해당 자막이 없음
    - 목표 시작 프레임에는 해당 자막이 있음
    - 목표 종료 프레임에는 다음 자막 또는 무자막 상태가 정확히 적용됨

11. 가사 원문의 행 수와 최종 ASS Dialogue 수를 비교한다.

12. 누락, 중복, 순서 변경, 잘못된 화자 색상을 허용하지 않는다.
