# 담다 로봇 화면 운영 안내

이 사이트는 직원이 보낸 요청과 승인된 음식 주문을 받아 안내 문장을 준비하는 독립적인 발표용 로봇 화면입니다. 이동·도착·완료는 직원이 버튼으로 바꾸는 **모의 진행 단계**이며, 실제 로봇을 제어하거나 위치·배달 완료를 감지하지 않습니다.

## 연결과 접근

- Sites에서 소유자 전용 비공개로 배포하고 D1 저장소를 `DB`로 연결합니다. `drizzle/`의 마이그레이션이 필요합니다.
- 화면과 모든 `/api/robot` 및 `/api/health` 요청에는 소유자 로그인 또는 서버용 `OPERATOR_TOKEN`이 필요합니다. `STAFF_OWNER_EMAIL`은 플랫폼의 이메일 전용 소유자 식별을 제한하는 값입니다. 고객 화면용 게이트웨이 인증은 직원 권한으로 인정하지 않습니다.
- 기존 직원 사이트의 로봇 수신 주소를 이 사이트의 `/api/webhooks/orders`로 설정합니다. 비공개 사이트 접근 자격과 양쪽이 공유하는 `WEBHOOK_SECRET`은 서버 비밀값으로만 설정합니다. 서명 수신 경로는 운영자 토큰 대신 플랫폼 접근 제한과 본문 서명을 검증합니다.
- 직원 요청은 직원이 **로봇에 전달하기**를 누른 뒤, 서명된 `staffApprovedAt`이 포함되어야 수신됩니다. 외국어 요청은 한국어 번역도 필요합니다. 음식 주문의 고객 승인 흐름은 기존 직원 사이트에서 유지합니다.
- 수신 시 원문·한국어·언어·테이블을 저장하고 빠르게 수신 확인을 반환합니다. 같은 이벤트는 중복 저장하지 않으며, 수신 확인 자체가 안내 생성이나 물리적 배달 완료를 뜻하지 않습니다.

## 서버 환경변수

`.env.example`에는 빈 이름만 있습니다. 실제 값은 배포 환경의 비밀값으로 주입하고 저장소·브라우저·로그에 넣지 않습니다.

| 용도 | 변수 |
| --- | --- |
| 수신 서명·직원 접근 | `WEBHOOK_SECRET`, `OPERATOR_TOKEN`, `STAFF_OWNER_EMAIL` |
| 기존 CLOVA Speech 연결 재사용 | `CLOVA_SPEECH_INVOKE_URL`, `CLOVA_SPEECH_SECRET` |
| 기존 Papago 연결 재사용 | `PAPAGO_CLIENT_ID`, `PAPAGO_CLIENT_SECRET` |
| 기존 CLOVA Studio 연결 재사용 | `CLOVA_STUDIO_API_KEY`, `CLOVA_STUDIO_MODEL` |
| 선택: 일일 안내·대화 처리 상한 | `ROBOT_DAILY_AI_LIMIT` (기본 200회, 최대 1,000회) |
| 선택: 별도 CLOVA Voice 연결 | `CLOVA_VOICE_CLIENT_ID`, `CLOVA_VOICE_CLIENT_SECRET` |

CLOVA Voice는 별도 연결입니다. Papago 자격증명이 음성 출력까지 허용한다고 가정하지 않습니다. Voice 키가 없으면 `capabilities.tts=false`, 음성 출력 요청은 `503 TTS_UNAVAILABLE`을 반환합니다. 화면에서 제공하는 기기 음성 읽기는 브라우저·기기의 대체 기능이며, 네이버 음성 출력과 구분합니다.

## 발표 순서와 보존 범위

1. 고객이 요청을 남기고 직원 화면에서 원문과 한국어를 확인한 뒤 로봇 전달 버튼을 누릅니다. 승인된 음식 주문도 같은 수신 경로로 들어옵니다.
2. 로봇 화면이 새 요청을 보여 주고 안내를 준비합니다. 한국어·영어·일본어·중국어 중 요청 언어로 답하며, 도움이 필요한 경우 직원 확인 상태를 표시합니다. 준비 실패는 명시적으로 다시 시도합니다.
3. 필요하면 말하기 버튼을 눌러 후속 대화를 녹음합니다. 원문을 그대로 보존하고 한국어 번역과 해당 언어 답변을 추가합니다. 대화가 음식 주문을 승인하거나 이동 단계를 바꾸지는 않습니다.
4. 직원이 준비 → 이동 중 → 도착 → 완료를 순서대로 선택합니다. 직원 확인 상태는 직원이 확인한 후 준비로 돌아갑니다. 완료 후 새 대화는 거절하지만, 이미 처리한 같은 요청 번호의 응답 복구는 허용합니다.

음성 녹음과 생성된 음성은 이 앱의 저장소에 저장하지 않습니다. D1에는 수신 요청, 대화 텍스트, 진행 상태, 중복 처리 정보와 사용량 제한 정보가 남습니다. 안내 생성과 번역·인식은 실제 공급자 연결을 사용하며, 연결 실패를 성공으로 꾸미지 않습니다. 알레르기 안전이나 물리적 배달 완료를 모델이 보장하도록 사용하지 않습니다.

## 로컬 검증

Node.js 22.13 이상이 필요합니다. 아래 테스트는 모의 공급자와 로컬 SQLite/Workers 실행 환경을 사용하며 실제 유료 API를 호출하지 않습니다.

```sh
npm ci
node --test tests/robot.test.mjs tests/robot-providers.test.mjs
npx tsc --noEmit
npm run build
npm run start
```

로컬 웹 요청에는 별도로 로컬 D1 마이그레이션과 서버 환경변수를 준비해야 합니다. 실제 연결 검증은 배포된 비공개 사이트에서 운영자 자격으로 수행하며, 소유자 로그인·서명 수신·같은 이벤트 재전송·안내 언어·모의 진행 단계를 구분해서 확인합니다.
